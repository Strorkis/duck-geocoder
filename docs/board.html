箇所何が特別か
配り方 (パイプライン)
crates/remote-zip HTTP Range を Read + Seek に見せ、zip の中身を落とさず取る。単体のクレートに切り出した (CLI 付き)
spatial_pack.rs / repack.rs STR で並べ、段 (lod) の境で行グループを切る。読み飛ばしが効くかはここで決まる
lod.rs 線の粗い段: 名前で束ねて簡略化した行を同じファイルに足す (原寸は消さない)
quadkey.rs · quadkey_sql.rs 同じ QuadKey を Rust と SQL の2通りで書き、テストで一致を見る。件数で割る深さを変える (choose_tiles)
catalog.rs の TIERS / Terms 重要度の段と使う条件を規則・データとして持ち、SQL (rank_sql) とカタログの両方へ出す
stac.rs STAC の置き方の判断 (サブカタログ、Item を1ファイルずつにしない、duck:* の独自項目)
stac_geoparquet.rs · stac_i18n.rs Item を Collection ごとの行グループに。フッターを削り、件数の少ないものをフッターの隣に置く (16KB 単位で読まれるため) / 英語版とまとめ。訳の無い日本語はエラー
external.rs · pmtiles.rs 外部の PMTiles をスナップショット (追跡) からカタログへ。テーマが層をちょうど覆うことを検証
使い方 (web/src/lib/ · ui/ と main.ts)
lib/stac.ts の fetchCollections · lib/duckdb.ts の collectionRows まとめ1つから Collection を作る (相対リンクはその文書からの相対)。Item は stac-geoparquet を行番号の範囲で読む (DuckDB は文字列の統計を頭でしか比べないため)
lib/sources.ts の filesInView · lodForZoom 表示範囲に重なるファイルだけを DuckDB に渡し、ズームから粗い段か原寸かを決める
lib/nearby.ts の toMeters · nearbyCondition 周辺検索: ST_Affine で起点付近をメートルに直してから ST_DWithin。当たった線は範囲で切り取る
lib/tiles.ts の vectorLayerSpecs · createVectorOverlay 地理院のタイルをデータだけ読み、形の種類から描く。入り切りはズームで戻さない
lib/tiles.ts の baseStyle · gsiDemHeight 背景地図と地形をカタログから組む。地理院の標高 (独自形式) は読み込むときに Terrarium へ詰め直す
ui/layers/buildings.ts の buildingDepth · lib/queries.ts の fetchBuildingsInView 1ズーム引くごとに1段減らす間引き (lod <= 段)。転送量の上限はここ
lib/wkb.ts · tests-unit/wkb.test.ts DuckDB が返す GeoArrow (WKB) を自前で読む (GeoJSON の文字列を作らない)。見本は DuckDB spatial で作った
ui/layers/context.ts データの描き方の共通の形 (世代を最初に進める・空なら setData しない)。各 refresh はこの形
lib/duckdb.ts の exportParquet ブラウザの中で GeoParquet を書き、出典と規約を KV に入れる
ui/layer-list.ts の applyOrder · startDrag 一覧の順番を地図の層へ写す (区分ごとの目印の層の直下に積む)。ドラッグは Pointer Events で、動きは window で拾う
ui/hover.ts の HOVER_LAYERS · ui/nearby-panel.ts の setFocusMode 吹き出しを層ごとの表で1つの仕掛けに (周辺検索の結果にも、指で押しても出る) / 周辺検索でほかの層を薄くして閉じたら戻す
stac-browser/ の items-base.patch · build.sh STAC Browser 5.1.0 にパッチを1つ当ててビルドする (相対の rel: items がページ基準で解決され 404 になる不具合)。rel: items が無くなったので今は効く場面が無い。上流で直ったら外す
判断の記録 (docs)
geoparquet-layout.md GeoParquet の並べ方と読み方を1か所に。問い合わせの形ごとの相性、テストで見えていない部分、COGP に返せそうなこと
duckdb-wasm-range-requests.md 部分取得が黙って全件取得に落ちる罠と、CORS の要件
data-sources.md の承認の節 測量法の承認が要るもの・要らないもの、描画用データを根拠にしない理由
pipeline.md の「粗い段」「段で間引く」 実測した転送量と、COGP を採らなかった数字

次にやること

  1. 配らずに手元で変換する仕組み (構想) PLATEAU GIS Converter のように、利用者が取ったデータをブラウザの中 (WASM) で変換する。 測量法のあるデータ (基盤地図情報) の扱いを地理院に確かめてから。3D Tiles のテクスチャもこの形で (roadmap)
  2. AW3D30 を地図に出すか 参照だけ足した。出すなら COG を直接読む部品が要る (R2 は使わない)。画像に「©JAXA」を出す。 NASA の2つはログインかトークンが要るので後回し
  3. Overture の出典を実際の出所に絞る 取り出しで sources 列を落としていて、日本にどの出所が入っているか数えていない。 いまは挙げられている出所を全部書いている。次に取り直すときに残して数える
  4. Item に名前と時点を入れる ⓘ の Item の一覧が plateau_bldg_01100 のような ID だけで、時点も無い。次に PLATEAU を書き換えるときに一緒に (306ファイルの上げ直しになるため)。 stac-geoparquet に列を足す形になる
  5. 3D の別モード (後で) Navara モード・Cesium モード。MapLibre ＋ Three.js (3DTilesRendererJS) で重ねる道も。Navara は試作で描けた。 案: 変換 (WASM → 3D Tiles) を先に作り、Cesium で確かめてから重ね方を決める
  6. 描き方 (スタイル) の置き場所 データと分けて、カタログの外か別の Collection として持つ案 (roadmap)
  7. 観点 (汎用の問い合わせのひな形) 条件をデータで持ち、用途ごとに組み替える。周辺検索が土台
  8. 国土数値情報を足す 学校 P29・医療 P04・福祉 P14・公共施設 P02・都市公園 P13。W05 (河川) は使えない
