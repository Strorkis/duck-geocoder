duck-geocoder ボード

更新: 2026-10-03

置いてあるデータを動かさずに、必要な分だけ取って、その場で使えるようにする実験。 サーバーを持たず、静的ファイル (STAC + GeoParquet) をブラウザの DuckDB-WASM で直接読む。 公開サイト

あなたの番

  1. R2にJSONを2つ上げて、push (公開中のサイトは止まらない) 建物の重要度の段の規則と名前が変わった。parquetは変わっていない 
    cd ~/duck-geocoder
R2=r2:duck-geocoder   # 前回と同じリモート名
mise exec -- rclone copy data/output "$R2" \
  --include '/plateau/plateau-buildings.json' \
  --include '/overture/overture-buildings.json' -P
git push
  2. 片付け (急がない) 手元の data/backup/r2-catalog-2026-10-01.json (戻すための控え。もう不要) と、 R2の plateau/plateau_bldg_minato.parquet (どこからも参照されない古い名前)
  3. 決めてほしいこと 下の「未決の問い」

次にやること (この順)

  1. 建物の粗い段 (間引き) 重要度の段で間引き、引いた表示では公共施設から出す。多めでもズーム14が限界なのは 転送量のため (画面に要る量の3〜15倍を読んでいる)。まず23区と前橋で試作して測る
  2. 観点 (汎用の問い合わせのひな形) 複数のデータにまたがる条件に名前を付けたもの。条件はコードではなくデータで持ち、 用途ごとに組み替えられるようにする (ドローンは例の1つ)
  3. 対象物の周辺検索 線 (道路・鉄道・送電線・川) や点を選び、○m以内に何があるかを出す
  4. ライセンスと商用利用の可否を一目で分かるように いまは識別子と出典だけ。「商用可か・表示義務・改変の扱い」を出したい
  5. 国土数値情報を足す 学校 P29 (最新年度はCC BY)・医療機関 P04・福祉施設 P14・公共施設 P02・都市公園 P13。 P04/P14 は許諾が未確認。河川 W05 は使えない (非商用・承認番号付き・2009年度で停止)
  6. Overtureの版を上げる 使っている 2026-07-22.0 がS3から消えた。取り直すときに要る。送電線もここから取る

待ち (こちらから動かせない)

  • 測量法の承認 (29条・複製) N03 行政区域・DID・川 (基盤地図情報の水涯線) がまとめて開く。 下準備は survey-application.md

未決の問い

  • 建物の間引きの基準 重要度の段を軸にする方向。段の中 (例えば住宅) をさらにどう減らすか
  • リポジトリの名前 duck-geocoder は実態から外れた。方針が文になってから選ぶ
  • 表示部分をライブラリにするか web/src/main.ts にデモと部品が混ざっている (約5,000行)

構想 (このリポジトリの外)

  • Rangeでzipの一部だけ取る道具を切り出す APIが無くても、Range Requestに応える配信元ならzipの中身を部分取得できる。 いまは pipeline/src/remote_zip.rs

やらないこと

  • 動的データ (気象・他機位置) をファイルで配る
  • 点群の生データを配る (TB級。派生物にする)
  • SDSP/UASLの文脈を深追いする・航路の設計そのもの
  • 認証が要る取得経路 (Foursquareの公式配布など)
