# 何を目指していて、何が積み残っているか

散らばっていた判断をここに集める。**新しく決める場所ではなく、
決まったことの索引。** 根拠は [data-sources.md](data-sources.md) と
[pipeline.md](pipeline.md) にある。

## 何の実験か

> **日本のオープンデータが STAC / Portolan を使った配布形式になっていったら
> どうなるか、を試す。**

このリポジトリを中心に据えたいわけではない。**正典のカタログを作るのではなく、
配り方を試している。** ここにあるのは変換した複製で、**原典は配布元**。

そのうえで、**元のデータを尊重しつつ使う側が便利になる**方向を意識する。
軸が2本ある。

## STAC配信への移行は済んだ (2026-09-19)

29コミットと209MBを載せ、**本番に対するE2E 46件が通った**。転送量は
`1.5 MB / 97.6 MB` のままで、部分取得は効いている。

配信は **73オブジェクト / 208MiB**。旧構造 (ルート直下のparquet) は削除済みで、
いまバケットにある階層は1つだけ。

### 次の配信で困ること

**PLATEAUを全国に広げると、いまの手順が通用しない。** 出力が5〜10GBになるので、
アップロード自体に相当な時間がかかる。着手前に上げ方を決め直すこと。

`catalog.json` の**構造**を変えるときは、上げた瞬間から新しいバンドルが載るまで
公開中のサイトが壊れる。順序は [deploy.md](deploy.md) に書いた。

## 軸1: 集めたいデータ

「全国を覆っているか」は使う・使わないの基準にしない
([data-sources.md](data-sources.md) の「出所ごとに何が言えるか」)。
**あるところでは精度の高いものを使う。**

| 欲しいもの | いま無い理由 | やるとしたら |
| --- | --- | --- |
| **PLATEAU 全国** | 配信元から84GB・5時間。出力5〜10GB。**306都市でUIが壊れる** | Itemごとのbboxで収録範囲を描き直す (下記) |
| **鉄道 (N02)** | 未着手。**承認は要らない** (下記) | 国土数値情報。**PLATEAU `rwy` は5都市しかない**ので全国のN02を使う |
| **道路** | 未着手 | PLATEAU `tran` (**302都市**) か 国土数値情報 **N13** (CC BY、2024年度に30年ぶり更新)。**N13は原典が複製承認なので扱いを確認する** |
| **学校・医療機関・福祉施設** | 未着手。「落ちてはいけない場所」 | 国土数値情報 P29 / P04 / P14。**P29は最新年度ならCC BY** (2013年度版は非商用) |
| **川** | **国土数値情報W05は使えない** (非商用 + 承認番号 + 2009年度で更新停止) | 基盤地図情報の水涯線 = **承認待ち**。Overtureは参考どまり |
| **昼間人口メッシュ** | 未着手。**手間の大半がダウンロード** (47回) で、出すのは既出の人口メッシュの別断面 | **`mesh_pop.rs` がそのまま使える。** 項目名を差し替えるだけ |
| **点群 (静岡・兵庫・東京都ほか)** | 生データはTB級。派生物にすると決めてある | COPC、またはDSMから作る障害物面。**カタログは同じSTAC** |
| **DID (人口集中地区)** | A16-2020の原典に国土数値情報 (行政区域) が入る | **行政区域の承認**に合わせる。系譜を避けるならe-Stat版 |
| **N03 (行政区域)** | 複製に**国土地理院長の承認**が要ると明記されている | 測量法の申請。**29条か30条かは要確認** (下記) |
| 送電線・鉄塔の高さ | **点群に分類が無い** (LAS 1.2にClass 14/15が無い) | 自前で分類する = 研究の領分 |
| 全国の障害物 (PLATEAU外) | 30m DSMは市街地で建物1棟が均される | 精度の割り切りを決める |
| 空港等の制限表面 | **面のGISが配られていない** (調査済み) | **C28 の標点・滑走路から計算で作る** (航空法第2条が数式で定義)。空港ごとに諸元が違う |
| 小型無人機等飛行禁止法の対象施設 | **機械可読で配られていない** (警察庁はPDF図面。原子力事業所はWeb非公開) | **無い。配れない** |
| 気象 (Open-Meteo) | **ファイルで配るものではない** (実行時API) | プレビュー側の機能として |

**手を付けやすい順** (手間と、待ちがあるかで並べたもの):

1. ~~**鉄道 (N02)**~~ — **済み (2026-09-20)。** 路線21,933件 / 駅10,234件。
   **駅は点ではなく線** (原典がホームの延長を線で持つ)。コードリストはzipに
   同梱されていないのでRust側の定数に写し、**未知のコードはエラー**にした
2. **道路** — PLATEAU `tran` なら**いま取れる** (302都市、変換の仕組みは建物と同じ)。
   全国が欲しければ N13 だが、**複製承認の扱いを確認してから**
3. **PLATEAUを広げる** — 変換の仕組みは出来ている。**先にUIを直す**必要がある (下記)。
   配信元から84GB、R2へ5〜10GB
4. **点群** — 形式 (COPC / DSMから作る面) と、どの派生物を作るかを決めるところから
5. 学校・医療機関 — 点データなので軽い。**P04・P14の許諾が未確認**
6. 昼間人口メッシュ — **下げた。**47回のダウンロードに対して、得られるのは
   既に出している人口メッシュの別断面
7. **川 / DID / N03** — **承認待ち。** こちらから動かせない
8. 空港の制限表面 — **面のGISは配られていないが、C28から計算で作れる**
   ([data-sources.md](data-sources.md))。ただし空港ごとに諸元が違う

**並べ替えの根拠は「手間の総量」ではなく「手動ダウンロードの回数」。** 変換コードを
足すのは安く、47回のクリックは高い。ここを取り違えて昼間人口メッシュを先頭に
置いていた。

### PLATEAUを広げると壊れるもの

仕組み自体は出来ている (`--cities all` は再開可能)。壊れるのはUIの2箇所。

- **「建物のある範囲へ移動」は収録範囲の和の中心へ飛ぶ。** 全国に広がると
  日本の真ん中の海に着く
- **収録範囲の枠も和なので、日本全体を囲む1つの箱になる**

Itemがファイルごとに `bbox` を持っているので、そこから描き直せばよい。
枠は都市ごとに、ボタンは「最も近い収録都市へ」。

## 測量法の承認申請 — 何がまとめて開くか

**方針は「国のデータを主に、Overtureは参考」。** これは撤回した「出所の格付け」
(全国を覆っていないものを外す) とは別物で、**OSM由来を根拠にしない**という
線引きの方。収録範囲の広さは理由にしない。

そのうえで詰まっているものは、ほぼすべて**同じ1つの手続きの先**にある。

| 欲しいもの | 承認が要るか |
| --- | --- |
| **鉄道 (N02)** | **不要。** 2020年以降は「適用する利用規約に基づく (オープンデータ)」 |
| **人口メッシュ・昼間人口** | 不要 (e-Stat、政府標準利用規約) |
| **N03 行政区域** | **要る** |
| **DID** | A16の原典に行政区域が入るので、N03に従う |
| **川 (基盤地図情報の水涯線)** | **要る** (基本測量成果) |

国土数値情報そのものは公共データ利用規約(PDL1.0)が既定で、**承認が要るのは
基本測量成果を背景図・原典に使っているものだけ**。個別ページの
「このデータの使用許諾条件」が正本なので、**データごとに読むこと。**
W05 河川はここで落ちた (非商用 + 承認番号 + 2009年度で更新停止)。

### 29条か30条かが、このリポジトリでは効く

| | | 二次利用 |
| --- | --- | --- |
| **第29条 複製承認** | 測量成果を**そのまま複製**する | さらに複製・使用するとき**申請が要る場合がある** |
| **第30条 使用承認** | 測量成果を**使って別のものを作る** | **申請不要** |

**ここが配布実験の成否に直結する。** 29条だと、この配信物を使う人が
自分で申請する羽目になりかねない。30条なら下流は自由になる。

GeoParquetへの変換・範囲の切り出しが「複製」なのか「使用」なのかは
自分で決められない。**申請前に国土地理院へ確認すること。**

申請は測量成果ワンストップサービス (オンライン)。**受理から承認まで約2週間。**

## UIの主役は geocoder (2026-09-20に決めた)

> 検索して飛んだ先で、**その場所に何があるか**が分かるのが理想。

**これは実験の主題と一致する。** STACの一番の効能は探索で、
「この場所にどのデータがあるか」は**bboxだけで、データ本体を読まずに答えられる**。

**済み:** データを**1データ1行のレイヤー一覧**にした (種別ごとに `<details>` を
積む形は、オープンデータを足すだけ縦に伸びて頭打ちが無かった)。
設定はパネルの中身と入れ替える。収録の無いものは「この範囲には無い」へ薄く移す。

**済み:** 駅名を検索に載せた (2026-09-20)。路線名でも引ける。
**駅名は人が実際に検索する語**で、地名と行政区域だけでは「東京駅」で何も出なかった。

**次:** 検索と連動させる。飛んだ先の**件数**まで出すと「何があるか」が具体になるが、
件数はカタログでは分からず問い合わせが要るので、**開いたときに数える**形になる。

### 検索をどこまでやるか

**既存のジオコーダ・検索エンジンは使えない。サーバーが要るため**
(Nominatim・Photon・Pelias・Groonga。詳細は [data-sources.md](data-sources.md))。
このアプリに実行時のサーバーは無い。

**当てはまるのは「静的な索引を分割して、要る断片だけ取る」形** (Pagefindがそれ)。
**これは空間に対して既にやっていること**で、軸が場所か語かの違いしかない。
ただし**いまは作らない** — 駅名8,503種は `ILIKE` の走査で足りている。
**遅いと分かってから。**

**住所は自前で書かない。** `normalize-japanese-addresses` (MIT) が
v3でABRベースに作り直されている。ABRは位置参照情報の後継にあたるが、
**置き換えは別の判断**。いま動いているものを壊してまで急がない。

| | 状態 |
| --- | --- |
| 行政区域・地名 | 使用中 (位置参照情報) |
| **駅名・路線名** | **使用中** |
| PLATEAUの建物名 | **入れない。**51,170棟中326棟 (0.6%) しか名前が無い |
| 住所の精度 (ABR) | 未着手。急がない |
| 分割索引 | 未着手。**遅くなってから** |

**既知の粗さ:** 判定に使っているCollectionのbboxは**ファイルの和**。
PLATEAUを全国に広げると「日本全体」になり、306都市の外でも「ある」と出る。
正確な範囲はItemにあるが、Itemは遅延読み込みなので起動時には見ていない。

## 軸2: 使う側の便利さ

**実験の主旨はここにある。** 配布元から落とすとPLATEAUのように巨大なzipになる。
変換して置いてあるのだから、使う側が楽になる道を用意したい。

| やりたいこと | いまの状態 | やるとしたら |
| --- | --- | --- |
| **配布元へたどり着く** | **済み。** STACの `rel: "via"` で出している (下記) | — |
| **必要な範囲だけ取る** | パイプラインはHTTP Rangeで部分取得している。**使う側には出していない** | 表示範囲を切ってダウンロード。DuckDB-WASMの `COPY ... TO` とバッファ取り出し |
| **GeoParquetで落とす** | 無い | 同上。GeoJSONも選べると一般には使いやすい |
| **ライセンスを持ち回る** | Collectionに `duck:attribution` がある | 切り出したファイルにも出典が付いて回る形 (GeoParquetのKVメタデータなど) |
| **承認番号を持ち回る** | 無い | 測量法の**二次利用では成果品名と承認番号の記載が要る** (N13なら `R6JHf503`)。出典表示に載せる場所が要る |
| **いつ時点か分かる** | **済み。** `duck:vintage` をGeoParquetのKVに書き、出典欄とホバーに出す | ファイルごとに版が違うもの (PLATEAUは都市ごとに更新年度が違う) はまだ埋めていない |

### 配布元へのリンク (実装済み)

STACの **`rel: "via"`** は仕様上「**このEntityが作られる元になったメタデータ/データ**」
を指す関係 ([best-practices](https://github.com/radiantearth/stac-spec/blob/master/best-practices.md))。
**出典表示のリンク先とは役割が違う** — Overtureは出典がガイドページを指すのに対し、
配布元はデータのページになる。

2段で持っている。

| | 何を指すか | どこから来るか |
| --- | --- | --- |
| **Collection** | その出所のダウンロードページ | `Description::via` |
| **Item** | **そのファイル1つの配布元** | GeoParquetの `duck:via` (変換時に書く) |

**PLATEAUは都市ごとにzipのURLが違う**ので、変換時に `duck:via` へ書いている。
分からないとき (手元のzipから変換した場合など) は**書かない。推測で埋めない。**

`optimize_geoparquet` はKVメタデータを解釈せずそのまま引き継ぐので、
空間パッキングを掛けても配布元は残る。

## 配信形式: MLT (MapLibre Tiles)

**これは寄り道ではなく本題。** Portolanは「ベクタは **GeoParquet + PMTiles**」と
決めていて、**MLTはその後半を置き換える候補**だから。配信形式の評価そのものなので、
下の「切り出しの基準」1に真っ直ぐ当てはまる。

2026-01-23に1.0。列指向で、**大きなタイルで最大6倍の圧縮・デコード約3倍**。
**MapLibre GL JS は対応済み**で、スタイルに `encoding: "mlt"` と書くだけ。
ロードマップが**明示的にOvertureとGeoParquetに寄せている**。

**このリポジトリには計測装置がある。** E2Eが転送量を実測している
(`1.5 MB / 97.6 MB`) ので、**圧縮率の主張を自分のデータで確かめられる。**

コスト: MLTは**タイル形式**なので、いまの「GeoParquetをDuckDB-WASMで直接引く」
経路とは別に**タイル化の工程が要る**。Planetilerの対応は近日段階。
置き換えではなく**2本目の配信経路**になる。

### Navara は立ち位置が違う

[Navara](https://github.com/maplibre/navara) (Re:Earth、2026-08に公開) は
**描画エンジン**なので、「配る」と「使う」で言えば完全に使う側。
**MapLibreを置き換える話にすると大仕事で、配り方の実験には何も足さない。**

ただしデモデータが**PLATEAU・国土地理院の写真タイル・Mapterhorn**で、
ここが使っているものとほぼ同じ。**アプリを書き換えず、Navaraに此処のSTACを
読ませてみる**なら、「別のエンジンから素直に読めるか」という配信側の検証になる。

## 気をつけること: ODbLの感染範囲

**再頒布そのものは4つとも認められている** ([README](../README.md) のライセンス節)。
問題になりうるのは**ODbLの同一ライセンス条項がどこまで及ぶか**。

いまは **Overture由来のファイルと他を別ファイルとして配っている**ので、
PLATEAUや国勢調査のものにODbLは掛からない。

**結合したファイルを作ると話が変わる。** 例えば「Overtureの行政区域で人口メッシュを
集計したファイル」を作ると、それが Derivative Database (ODbLが及ぶ) なのか
Collective Database (及ばない) なのかという判断が要る。

**軸2の「必要な範囲だけ取る」でも同じことが起きる。** 切り出したものが
複数の出所をまたぐなら、出力に**どの出所が混ざっているか**が分かる形にしないと、
受け取った側がライセンスを判断できない。

## 切り出しの基準

「別リポジトリに分けるか」という問いへの答え。**いまは分けない。**

1. **配信形式が増えるだけなら、同じカタログ。** STACは形式を問わない。
   Portolanが「ベクタはGeoParquet + PMTiles、ラスタはCOG、点群はCOPC」を
   1つの仕様にしているのはそのため。**COPCを足すのに別リポジトリは要らない**
2. **実行時に外部APIを叩くものは、データ層に入れない。** プレビュー側の機能
3. **分かれ目はデータの種類ではなく「配る」と「使う」の間。**
   いま `web/` が両方やっている。判断ロジック (SORAの計算、航路生成) が
   育ったら、そこが切れ目になる

## Portolan について

[Portolan](https://www.portolan-sdi.org/) は同じ構成 (オブジェクトストレージに
静的ファイル + STAC + GeoParquet) を仕様にしたもの。**まだ準拠していない。**

> Every catalog and collection carries `catalog.json` or `collection.json` for machines,
> plus `README.md` and `AGENTS.md` for people and agents.

Portolanが求める `README.md` / `AGENTS.md` は**配信するデータの側**に置くもので、
このリポジトリのAGENTS.mdとは別物。`data/output/` 側にはまだ無い。

準拠を名乗るのはv1.0が見えてから。v0.2.0で破壊的変更が予告されている。

## やらないこと

- **動的データ (気象・他機位置) をファイルで配ること。** 配れるものではない
- **点群の生データを配ること。** TB級。持つなら派生物にする
- **SDSP/UASLの文脈を深追いすること。** どんなデータが求められているかの
  参考にはするが、目的には掲げない
